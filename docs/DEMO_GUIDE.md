# QueueFlow MAI — сценарий демонстрации

## Подготовка

1. Запустите backend и frontend по README.
2. Откройте `http://localhost:5173` в основном окне.
3. Подготовьте приватное окно для student page.
4. При желании заранее запустите `python seed_demo.py` и сохраните выведенные ссылки.

## Показ буквально по кликам

1. На главной оставьте «Численные методы», выберите завтрашнюю дату, 12:00–14:00, ГУК Б-315, слот 10 минут, буфер 2 минуты, лимит 10.
2. Нажмите «Создать очередь».
3. Покажите public link, QR-код и отдельную секретную teacher link.
   Если показываете сканирование телефоном, запустите backend с `--host 0.0.0.0` и введите локальный IPv4 ноутбука в поле под QR. Не сканируйте QR с `127.0.0.1`.
4. Скопируйте public link и откройте в приватном окне.
5. Выберите 12:00. Введите «Арман Саркисян», «М8О-301Б-23», «ЛР 1.3». Нажмите «Записаться».
6. Покажите confirmation card с датой, временем, позицией, аудиторией и лабораторной.
7. Откройте teacher link: Арман уже появился без refresh.
8. Добавьте Марию на 12:12, Давида на 12:24 и Анну на 12:36.
9. В строке Армана нажмите «Начать». Покажите блок «Сейчас сдаёт» и «Следующий».
10. Нажмите «Отметить “Сдал”».
11. Отмените Марию через красную кнопку или student cancellation.
12. Покажите автосдвиг: Давид стал 12:12, Анна — 12:24.
13. Отметьте студента «Опоздал», затем нажмите «Перенести».
14. Обновите обе страницы: данные и статусы сохранились.
15. Откройте `/docs` и коротко покажите documented REST API.

## Что говорить

«QueueFlow решает один болезненный сценарий вместо попытки заменить LMS. Преподаватель создаёт окно сдачи за минуту и отправляет одну ссылку. Студент выбирает время без переписки, а отдельный Queue Engine централизованно рассчитывает позиции и расписание. При отмене или опоздании очередь пересчитывается по предсказуемому правилу COMPACT. Public и teacher actions разделены случайными токенами. Слот защищён транзакцией и уникальным ограничением базы, поэтому два студента не могут занять одно время. Для локальной разработки используется SQLite, production переключается на PostgreSQL одной переменной `DATABASE_URL`. Полный demo flow покрыт автоматическим browser E2E».

## Возможные вопросы

**Почему polling, а не WebSocket?**  
Для Quick Win polling раз в 2 секунды проще и устойчивее на бесплатном hosting. API и frontend изолируют обновление данных, поэтому транспорт можно заменить на SSE/WebSocket без переписывания Queue Engine.

**Как исключена двойная запись?**  
Backend повторно проверяет слот внутри транзакции. В базе действует unique constraint на `(session_id, slot_index)`. Даже при гонке только один commit успешен, второй запрос получает HTTP 409.

**Почему нет регистрации?**  
Это сознательное ограничение презентации. Public link даёт только просмотр и запись, booking token — отмену своей записи, secret admin link — управление. Для production следующего уровня можно добавить MAI SSO и отзыв admin sessions.

**Где реализован пересчёт?**  
В `backend/app/services/queue_engine.py`. Endpoints вызывают один сервис, поэтому формула времени и правила сдвига не дублируются.

**Что происходит при опоздании?**  
Статус LATE временно убирает запись из расписания и сдвигает следующих. Кнопка «Перенести» ставит студента в ближайший допустимый свободный слот.

**Как перейти на PostgreSQL?**  
Задать `DATABASE_URL=postgresql+psycopg://...` и выполнить `alembic upgrade head`. Код и модели менять не нужно.

**Что будет следующим после MVP?**  
MAI SSO, SSE/WebSocket, Telegram notifications, timezone support, аудит действий преподавателя, экспорт в календарь и метрики фактической длительности сдачи.
