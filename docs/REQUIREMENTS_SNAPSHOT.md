# QueueFlow MAI — Requirements Snapshot

## Цель и проблема

QueueFlow MAI заменяет ручную очередь в групповом чате на прозрачное расписание сдачи лабораторных. Преподаватель за минуту создаёт окно сдачи и отправляет одну ссылку. Студент за 1–2 минуты выбирает свободное время, вводит ФИО, группу и лабораторную, затем получает подтверждённое место.

## MVP и Happy Path

1. Преподаватель задаёт дату, время, аудиторию, длительность слота, буфер и лимит.
2. Сервис создаёт отдельные случайные public/admin ссылки и QR-код.
3. Студент открывает public link, выбирает слот и подтверждает запись.
4. Запись появляется в live-очереди и teacher dashboard.
5. Отмена освобождает слот и в режиме COMPACT сдвигает последующие записи.

## Динамическая очередь

- Время слота: `start_time + slot_index × (slot_duration + buffer)`.
- Активные записи уникальны по `(session_id, slot_index)`; конкурентная попытка получает HTTP 409.
- Отмена обнуляет слот отменённой записи и сдвигает все более поздние записи на один слот.
- Статусы: BOOKED, WAITING, CURRENT, PASSED, CANCELLED, LATE.
- LATE временно убирает студента из расписания и сдвигает очередь; teacher action «Перенести» ставит его в ближайший допустимый слот в конце активной очереди.
- CURRENT и NEXT вычисляются централизованно Queue Engine.

## Ограничения и доступ

- Без регистрации, OAuth и LMS-функций.
- Public token разрешает просмотр и запись; персональный booking token — отмену своей записи; admin token — управление.
- SQLite локально, PostgreSQL через `DATABASE_URL` в production.
- Live UX через polling каждые 2 секунды.

## Приёмка и демонстрация

Создание окна, ссылки и QR; четыре записи с шагом 12 минут; отмена второй записи и автоматический сдвиг; смена CURRENT/PASSED; отображение текущего и следующего; сохранность после refresh; одновременная запись в один слот допускает только один запрос. Backend покрыт pytest, Queue Engine тестируется отдельно.
