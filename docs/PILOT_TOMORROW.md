# QueueFlow MAI — пилот завтра

## Сегодня вечером

1. Откройте production URL и проверьте `/api/health`: ожидаются `status: ok` и `database: ok`.
2. Запустите `python pilot_check.py https://<production-domain>` и дождитесь `[PASS]` и `[CLEANUP] ... = 204`.
3. Создайте настоящую очередь на завтра. Сохраните teacher URL отдельно; студентам отправляйте только public URL.
4. Откройте public URL с телефона по мобильному интернету, сделайте одну тестовую запись и отмените её.
5. Сохраните CSV и скриншот teacher URL в личное место. Teacher URL — секрет.

## Утром за 15 минут

1. Разбудите бесплатный cloud-сервис открытием `/api/health`; первый ответ после простоя может занять около минуты.
2. Откройте teacher URL и убедитесь, что вчерашняя очередь и записи сохранились.
3. Проверьте public URL на телефоне, QR и свободные слоты.
4. Запустите `python pilot_check.py https://<production-domain>`; скрипт удалит только свою очередь `[PILOT-CHECK]`.
5. Держите teacher dashboard открытой на ноутбуке и зарядку подключённой.

## Сообщение студентам

> Завтра записываемся на сдачу через QueueFlow: <PUBLIC_URL>. Выберите свободное время, укажите ФИО, группу и лабораторную. После записи сохраните личную ссылку — по ней можно проверить время или отменить запись. Секретную преподавательскую ссылку никому не пересылайте.

## Во время пилота

- Студент показывает экран «Вы записаны»; преподаватель работает только в teacher dashboard.
- `CURRENT` — сдаёт сейчас; затем `PASSED`. `LATE` временно убирает из расписания и позволяет перенести. `CANCELLED` финально отменяет и уплотняет COMPACT-очередь.
- Если два студента выбрали один слот, один получит запись, второй — понятный конфликт и выбирает другой слот.
- После занятия скачайте CSV из teacher dashboard.

## Emergency recovery

### Cloud недоступен, но интернет есть

1. Проверьте `/api/health`. Если сервис просыпается — подождите до 90 секунд и обновите страницу.
2. В Render откройте последний deploy/logs; не меняйте `DATABASE_URL`. Выполните redeploy последнего успешного commit.
3. Если web работает, а `database: unavailable`, проверьте состояние PostgreSQL в Render. Не создавайте новую БД поверх старой.

### Cloud или интернет не восстановились

1. Ноутбук и телефоны подключите к одной Wi-Fi сети/точке доступа.
2. В корне проекта запустите `powershell -ExecutionPolicy Bypass -File .\start_local_pilot.ps1`.
3. Скрипт применит migrations, запустит production-like сервер и напечатает LAN URL.
4. Создайте новую локальную очередь, покажите QR и отправьте LAN public URL. Он работает только в этой сети.
5. Не закрывайте окно PowerShell. После занятия скачайте CSV.

Локальный fallback использует отдельную SQLite БД и не содержит cloud-записи. Если критична уже существующая очередь, продолжите по заранее сохранённому CSV/списку и не обещайте автоматическую синхронизацию.
